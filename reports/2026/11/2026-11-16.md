## 三个跨产品需求信号（INFERRED）

1. **共享 Agent 需要权限和技能版本溯源**：Frevana 技能版本缺口、Rakazo 预算边界、Talyn 沙盒凭据/自动推送问题，构成需求线索，付费意愿未知。
2. **垂直软件的交易闭环可能胜过泛化功能**：TwoBucket 从车况到定金、复购，Tulvo 从表单到数据库；反证是细分市场获客困难与一体化平台迁出成本。
3. **减少上下文断裂**：Remindly 合并笔记和提醒，collecto.rs 合并收藏类别；但数据迁移损失与识别错误可能抵消收益。

## 两周创业实验：Agent Run Provenance Lite

**人群**：2–10 人共享 Agent 技能及 GitHub PR 的开发团队。**MVP**：Python CLI + SQLite + 静态 HTML，只保存沙盒模拟的 skill hash、执行主体、审批决策、工具调用及 PR SHA，不读取密钥、不触碰生产系统。**访谈**：8 位开发者，要求给出最近一次脱敏故障而非口头购买意愿。**试验**：5 支团队各执行 3 个模拟场景，盲测有无 provenance 时的定位耗时。**成功阈值**：≥4/8 有近期痛点、≥3/5 重复使用、定位时间中位数下降 ≥30%，无敏感数据泄露。**失败阈值**：≤1/5 重复使用，或现有 Git/日志已足够，或维护成本超过节约时间。阈值是预注册标准，不是实验结果。

## 相比此前研究的变化与局限

从 Agent 事前授权、执行后审计，进一步转向多人共享技能的版本溯源；同时 TwoBucket 提醒我们不应把创新局限于 AI，细分线下交易工作流同样值得验证。没有独立转化率、留存、融资事件、完整失败创业者访谈；不能把连续出现类似产品当作市场需求增长的定量证据。
