# Agent Change Review Lite — 2026-11-13

研究假设（非已证实需求）：多个 Agent 对共享知识库、文档或发布产物进行并行改动时，审查、版本回滚与证据记录可能成为独立付费场景。

## 观察依据

- [Omnigraph](https://www.omnigraph.dev/)：厂商公开强调图谱分支、类型约束、审查合并。
- [three.dev](https://three.dev/)：厂商展示线上 Agent 语义失败聚类与修复前后比较，演示数字不能当真实客户指标。
- [Spacefast](https://spacefast.com/)：厂商提供 Agent 发布、私有分享、版本恢复与评论。

## 反证与缺口

现有 Git、数据库事务、Notion 历史版本、CI 审批可能已解决大部分需求；尚无独立证据证明小团队愿意额外付费。三个产品之间仅是分析者发现的需求主题相近，不代表已经审核的商业关联。

## 两周可证伪实验

目标：2–10 个 Agent 并行改动文档/知识库的小型开发团队。MVP：本地 Python/SQLite + HTML diff、变更来源、批准/拒绝、回滚，使用脱敏沙盒数据。访谈 8 人，5 人试用一周。成功：≥4/8 有近期可核实的重复冲突痛点、≥3/5 重复使用、复盘时间中位数下降 ≥25%；失败：<2/5 重复使用或审批开销超过节省时间。全部结果预注册并保留负面反馈。
